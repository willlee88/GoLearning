H4 · 權威 Server：客戶端送意圖，真相在你這邊

Authoritative server——可以預測顯示，但不能讓客戶端自稱 HP=999。校驗、套用、再廣播。

範例路徑：examples/h06-apply-input · 完整原始碼在本頁下方

authoritativegame-server

這章你會搞懂什麼

權威伺服器（authoritative server）的意思很白話：

遊戲世界的真相只住在 Server。客戶端可以畫得漂亮、甚至先預測，但提交的是「我想做什麼」，不是「世界已經變成怎樣」。

對照：

客戶端送來的東西 好不好
{ "x": 999, "y": 999, "hp": 999 } 自稱狀態 壞：等於把管理員權限交給每個人
{ "dx": 1, "dy": 0 } 移動意圖 好：Server 自己算新座標

讀完這章，你會知道為什麼教學早期的「點一下傳座標」只能當捷徑，以及正式一點的 input 路徑長什麼樣。

Python 對照

別把即時遊戲做成「客戶端 POST 一整份存檔，Server 存起來再轉發」。
比較像：

客戶端：我按了右鍵（意圖）
伺服器：依規則模擬一步（權威）
再告訴大家：現在世界長這樣（快照／事件）

這跟「信任前端算完的購物車總價」是同一類雷——只是遊戲裡被濫用的後果是飛天、秒殺、全圖透視。

怎麼寫（好壞封包對照）

壞：客戶端自稱狀態

{ "type":"state", "payload": { "x":999, "y":999 } }

Server 若照單全收再廣播，等於協助作弊擴散。

好：客戶端送意圖，Server 計算

{ "type":"input", "payload": { "dx":1, "dy":0 } }

Server:
  校驗 phase、dx/dy 範圍、速率…
  x = clamp(x + dx*speed, 0, width)
  廣播權威 state

最小邏輯可以參考 examples/h06-apply-input（H6 會更細講佇列；這章先抓住「誰擁有真相」）：

func (r *Room) PushInput(in Input) error {
	if r.Phase != PhasePlaying {
		return ErrInvalidPhase
	}
	if abs(in.DX) > 1 || abs(in.DY) > 1 {
		return fmt.Errorf("%w: dx dy must be -1..1", ErrBadInput)
	}
	r.inbox = append(r.inbox, in)
	return nil
}

func (r *Room) Tick() {
	// 依 inbox 更新 Players[i].X/Y——座標只在這裡被改
}

客戶端顯示可以立刻往右偏一格（預測），但若 Server 回來說「你其實撞牆了」，以 Server 為準把畫面拉回來。

為什麼要權威（不用會怎樣）

1. 防作弊的基線

權威不等於「反作弊畢業」，但沒有權威，連基線都沒有：

  • 邊界（不能走出地圖）
  • 速度（不能一幀飛全圖）
  • 冷卻（技能不能無 CD 狂放）
  • 視野（不該知道霧戰外的資訊就別廣播）

客戶端代碼一定可被改——手遊、網頁、PC 都一樣。把判決放在客戶端，就是把鎖放在門外。

2. 同步比較好談

大家看到的「世界」都來自同一份 Server 狀態（或同一份狀態的投影）。
若每人本地各改各的再偶爾對一下，分叉會像兩人各寫各的 Google 文件又不合併。

3. 單機 demo 也要走權威

「反正沒有外掛玩家」不是理由。肌肉記憶要趁現在練：
input in → state out。之後接多人、接匹配、接觀戰都比較順。

進階可先略過

  • 客戶端預測 + 和解（reconciliation）：本地先模擬，等 Server 快照再修正。體感延遲更好，實作較難。
  • 鎖定步／幀同步（lockstep）：大家只交換輸入、各自模擬——即時競技與 RTS 常見變體，但對延遲與確定性要求高。
  • 深度反作弊、伺服器側重放、行為異常偵測 → 之後 J 卷再碰；別跟「權威」混成同一件事。

遊戲 Server 會用在哪

本站演進很重要的一刀：

  • 較早的捷徑：客戶端傳 pos（點擊座標）——好懂、好 demo
  • M4 Arena Mini：改成傳 input 方向，座標只在 Server

你在 H10 檢查清單會看到：「客戶端不再直傳權威座標當真相」。這不是吹毛求疵，是整卷的脊樑。

請丟掉的舊習慣

  1. 信任前端算完的結果（座標、傷害、背包、金錢）。
  2. 把同步當成「把我的變數複製給所有人」——複製的是權威快照，不是客戶端私貨。
  3. 為了少寫幾行，讓客戶端直接改 Room 狀態——捷徑會變成協定。
  4. 認為「加密一下封包就夠了」——加密防的是竊聽，不是「合法客戶端被改邏輯」。

動手練習

必做

  1. 用自己的話說明：為什麼正式遊戲裡 pos 直傳很危險（至少寫兩點：作弊、不一致）。
  2. 設計一個 input payload 的三個欄位（例如玩家 id、dx、dy；或加上序號）。說明 Server 會拒絕什麼值。

選做

  1. 跑 examples/h06-apply-input 的測試，看「壞輸入」與「Lobby 就送 input」如何失敗。
  2. 想一個「看起來像狀態、其實是意圖」的技能施放封包，並寫下 Server 還要校驗什麼。

常見坑

  • 廣播了 state，卻仍接受客戶端 state 寫回：雙通道會讓權威名存實亡。
  • 只校驗「有沒有登入」，不校驗數值範圍：dx=999 一樣飛天。
  • 視野資料全圖廣播：沒改座標也可能作弊（透視）。權威要配合「該讓你看多少」。
  • 教學捷徑留到上線：pos 直傳若進正式環境，等於公開後門。

func TestApplyInputAuthoritative(t *testing.T) {
	r := game.NewRoom(100, 100, 5)
	r.Add("Ada", 10, 10)
	r.Start()
	if err := r.PushInput(game.Input{Player: "Ada", DX: 1, DY: 0}); err != nil {
		t.Fatal(err)
	}
	r.Tick()
	if r.Players["Ada"].X != 15 {
		t.Fatalf("x=%d", r.Players["Ada"].X)
	}
}

func TestRejectBadInput(t *testing.T) {
	r := game.NewRoom(100, 100, 5)
	r.Add("Ada", 0, 0)
	r.Start()
	err := r.PushInput(game.Input{Player: "Ada", DX: 5, DY: 0})
	if !errors.Is(err, game.ErrBadInput) {
		t.Fatalf("%v", err)
	}
}

func TestInputInLobbyFails(t *testing.T) {
	r := game.NewRoom(100, 100, 5)
	r.Add("Ada", 0, 0)
	err := r.PushInput(game.Input{Player: "Ada", DX: 1, DY: 0})
	if !errors.Is(err, game.ErrInvalidPhase) {
		t.Fatalf("%v", err)
	}
}
game.go
package game

import (
	"errors"
	"fmt"
)

var (
	ErrBadInput     = errors.New("bad input")
	ErrInvalidPhase = errors.New("invalid phase")
)

type Phase int

const (
	PhaseLobby Phase = iota
	PhasePlaying
)

type Input struct {
	Player string
	DX, DY int
}

type Player struct {
	Name string
	X, Y int
}

type Room struct {
	Phase   Phase
	Width   int
	Height  int
	Speed   int
	Players map[string]*Player
	inbox   []Input
}

func NewRoom(w, h, speed int) *Room {
	return &Room{
		Width:   w,
		Height:  h,
		Speed:   speed,
		Players: map[string]*Player{},
	}
}

func (r *Room) Add(name string, x, y int) {
	r.Players[name] = &Player{Name: name, X: x, Y: y}
}

func (r *Room) Start() { r.Phase = PhasePlaying }

func (r *Room) PushInput(in Input) error {
	if r.Phase != PhasePlaying {
		return ErrInvalidPhase
	}
	if abs(in.DX) > 1 || abs(in.DY) > 1 {
		return fmt.Errorf("%w: dx dy must be -1..1", ErrBadInput)
	}
	if _, ok := r.Players[in.Player]; !ok {
		return errors.New("unknown player")
	}
	r.inbox = append(r.inbox, in)
	return nil
}

// Tick applies queued inputs once (last input per player wins).
func (r *Room) Tick() {
	if r.Phase != PhasePlaying {
		return
	}
	last := map[string]Input{}
	for _, in := range r.inbox {
		last[in.Player] = in
	}
	r.inbox = r.inbox[:0]
	for name, in := range last {
		p := r.Players[name]
		p.X = clamp(p.X+in.DX*r.Speed, 0, r.Width)
		p.Y = clamp(p.Y+in.DY*r.Speed, 0, r.Height)
	}
}

func abs(v int) int {
	if v < 0 {
		return -v
	}
	return v
}

func clamp(v, lo, hi int) int {
	if v < lo {
		return lo
	}
	if v > hi {
		return hi
	}
	return v
}
