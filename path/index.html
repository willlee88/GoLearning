主學習路徑

建議順序。標示 stub 的章節為佔位，可先跳過。 完成 P0 後進入 A 卷；併發請認真走完 C 卷。

  1. 01A0 · 先看這卷要學什麼（語言地基）a · l1 · ready

    A 卷在幹嘛：從安裝、package、零值，一路到 slice／map／struct，幫你把 Go 的資料與型別想清楚。

  2. 02A1 · 先把 Go 裝好，跑出第一個 modulea · l1 · ready

    安裝官方工具鏈、認識 go.mod，用最小程式確認「能建、能跑」。

  3. 03A2 · package：誰能看見誰（大寫才匯出）a · l2 · ready

    同一個目錄就是編譯邊界；名稱大寫才能給別的 package 用——比 Python 底線約定硬很多。

  4. 04A3 · 變數、零值、常數與 iotaa · l2 · ready

    宣告了就有預設值；用 const／iota 把狀態與列舉寫清楚，少靠字串魔法。

  5. 05A4 · 控制流：if、for、switch（就這麼精簡）a · l2 · ready

    只有一種 for、條件一定是 bool、短宣告有作用域；房間狀態機很適合用 switch 寫。

  6. 06A5 · 函式與多回傳：（結果, error）文化a · l2 · ready

    參數怎麼傳、多回傳怎麼寫；為什麼失敗用回傳值，而不是丟例外。

  7. 07A6 · defer：離開函式前一定做的事a · l2 · ready

    延遲執行、後進先出；關檔、解鎖、取消 context 的標準寫法。

  8. 08A7 · 指標：什麼時候要共享同一份資料a · l2 · ready

    預設是值拷貝；需要改同一份或表達「可選」才用指標。沒有指標運算，但有 nil。

  9. 09A8 · slice 與 map（本卷超重要檢查點）a · l2 · ready

    slice 是底層陣列的視圖；map 是雜湊表引用。共享、append、併發寫入，都是實戰雷區。

  10. 10A9 · 字串、rune 與 []byte：別把「字」當 bytea · l2 · ready

    string 是不可變 UTF-8；索引拿到的是 byte。處理中文暱稱與聊天要用 rune。

  11. 11A10 · struct 與 tag：把一筆資料描述清楚a · l2 · ready

    用 struct 建模；tag 掛 json 之類中繼資料。組合靠嵌入，不是繼承樹。

  12. 12A11 · method：值接收者還是指標接收者？a · l2 · ready

    方法就是帶 receiver 的函式。要改狀態多用指標；方法集會影響能不能塞進介面。

  13. 13A12 · interface：描述「會做什麼」，不是繼承a · l2 · ready

    方法集對了就算滿足介面；越小越好用。另外：nil 指標塞進介面後，介面不一定是 nil。

  14. 14A13 · 型別斷言與 type switch：從介面拿回具體型別a · l2 · ready

    手裡只有介面時怎麼分支；comma-ok 才安全。遊戲訊息分派很常用。

  15. 15A14 · 泛型：好用，但請克制a · l2 · ready

    型別參數適合容器與演算法；別把房間規則寫成天書。到這裡 A 卷主路徑告一段落。

  16. 16B0 · B 卷導讀：錯誤是值，API 要好維護b · l1 · ready

    把 error 當值來設計；學會包裝、哨兵、panic 邊界，以及清楚的建構慣例。

  17. 17B1 · error 是值：哨兵錯誤怎麼用b · l2 · ready

    搞懂 error 介面、哨兵 ErrXxx，以及為什麼要比對值而不是比對字串。

  18. 18B2 · wrap：幫錯誤加上上下文，還留得住根因b · l2 · ready

    用 fmt.Errorf 與 %w 把「哪一步失敗」寫進錯誤鏈，並用 Is/As 往下找。

  19. 19B3 · panic 跟 recover：什麼能炸、在哪接住b · l2 · ready

    panic 不是業務例外；學會只在邊界 recover，避免一條連線拖垮整個行程。

  20. 20B4 · API 慣例：好測、好組、少驚喜b · l2 · ready

    接受小介面、回傳具體型別；用 NewX 保證不變式，錯誤可被 Is/As。

  21. 21C0 · C 卷導讀：併發——遊戲 Server 的中樞神經c · l1 · ready

    搞懂誰擁有資料、怎麼停、怎麼證明沒 race。goroutine／channel／sync 都為這三件事服務。

  22. 22C1 · goroutine：開得起，也要關得了c · l2 · ready

    go 關鍵字很便宜，但不是免費；學會 WaitGroup、停止條件，以及常見洩漏長什麼樣。

  23. 23C2 · channel：通訊、同步，以及誰能 closec · l2 · ready

    無緩衝是交接、有緩衝是佇列；搞清楚擁有者，才不會對已關閉的 channel 傳送而 panic。

  24. 24C3 · select：同時等很多路，含超時c · l2 · ready

    多路等待命令／tick／取消；用 timer 做超時，用 default 做非阻塞嘗試。

  25. 25C4 · context：取消是一棵樹c · l2 · ready

    WithCancel／Timeout 怎麼往下傳；Done／Err 怎麼用；Value 為什麼要克制。

  26. 26C5 · Mutex：沒有 GIL，共享就要同步c · l2 · ready

    鎖的粒度、defer Unlock、RWMutex；以及何時該改用「單一擁有者 + channel」。

  27. 27C6 · Race Lab：先紅後綠，親眼看見 data racec · l2 · ready

    用 go test -race 讀報告、修好共享寫入——這是 C 卷檢查點。

  28. 28D0 · D 卷導讀：能跑之後，要能維護d · l1 · ready

    把程式變成可依賴、可測、可進 CI 的工程：modules、表驅動測試、fuzz、bench／pprof。

  29. 29D1 · go.mod：依賴要可重現，不要碰運氣d · l2 · ready

    module path、語意化版本、go.sum，以及 Minimal Version Selection 的白話意思。

  30. 30D2 · 表驅動測試：加案例像填表d · l2 · ready

    用 cases 表格 + t.Run 變成肌肉記憶；遊戲狀態機特別吃這套。

  31. 31D3 · Fuzz：亂餵輸入，抓你以為不會發生的事d · l2 · ready

    Go 內建 fuzz：給種子、自動長出怪字串，專治封包解析與邊界假設。

  32. 32D4 · Benchmark 與 pprof：先測量，再談優化d · l2 · ready

    用 testing.B 看 ns／op 與記憶體分配；用 pprof 找 CPU／heap 熱點——別靠感覺改碼。

  33. 33F0 · F 卷導讀 · 網路f · l1 · ready

    從 TCP/HTTP 到 WebSocket：遊戲 Server 的連線層。

  34. 34F1 · 網路心智模型f · l2 · ready

    延遲、吞吐、丟包與遊戲手感；可靠傳輸不等於即時。

  35. 35F2 · TCP server 與 clientf · l2 · ready

    net.Listen、Accept、連線生命週期。

  36. 36F3 · 封包邊界與長度前綴f · l2 · ready

    TCP 是流：粘包/拆包與 length-prefix 幀。

  37. 37F4 · net/http 基礎f · l2 · ready

    Handler、ServeMux、狀態碼與 JSON API。

  38. 38F5 · 中介層與路由模式f · l2 · ready

    logging、auth、recover 的 Handler 包裝。

  39. 39F6 · WebSocket 原理與實作f · l2 · ready

    HTTP 升級、幀、與瀏覽器互通。

  40. 40F7 · 心跳、重連與會話f · l2 · ready

    連線≠玩家；閒置檢測與重連綁定概念。

  41. 41F8 · Lab：WebSocket 房間廣播f · l2 · ready

    F 卷檢查點：多房間、JSON 信封、廣播。

  42. 42G0 · G 卷導讀 · 序列化與協定g · l1 · ready

    訊息形狀、版本化、命令與事件分離。

  43. 43G1 · JSON 信封實務g · l2 · ready

    type + payload + v；成本與除錯優勢。

  44. 44G2 · 命令與事件分離g · l2 · ready

    client 下指令；server 廣播權威結果。

  45. 45G3 · 版本化與相容策略g · l2 · ready

    v 欄位、容錯解碼、棄用路徑。

  46. 46H0 · H 卷導讀 · 遊戲 Server 核心h · l1 · ready

    連線會了之後，局怎麼跑？Session、Room、Tick、權威狀態——把網路層變成可玩的一局。

  47. 47H1 · 遊戲後端職責地圖：誰管連線、誰管規則h · l2 · ready

    Gateway、Room、Rules、Persist 各做什麼、不該碰什麼；單進程也能先把腦裡分層畫清楚。

  48. 48H2 · Session 與連線：斷線不等於玩家蒸發h · l2 · ready

    Connection 是 socket；Session 是玩家在線上下文。進房、斷線、重連要分開想。

  49. 49H3 · Room 生命週期：用狀態機管准許的操作h · l2 · ready

    Lobby → Playing → Ended。非法操作回 error，不要默默忽略或 panic；集中用 phase 判斷。

  50. 50H4 · 權威 Server：客戶端送意圖，真相在你這邊h · l2 · ready

    Authoritative server——可以預測顯示，但不能讓客戶端自稱 HP=999。校驗、套用、再廣播。

  51. 51H5 · Tick：固定心跳推進模擬h · l2 · ready

    用 fixed timestep 累積輸入、推進狀態、再廣播。time.Ticker + select，而不是收到一包就改世界。

  52. 52H6 · 輸入佇列與校驗：先排隊，tick 再套用h · l2 · ready

    WS 讀到的是意圖：validate → enqueue；Tick 時再 apply。範圍檢查、相位檢查、合併策略。

  53. 53H7 · 狀態同步：先全量快照，再談省流量h · l2 · ready

    全量 State vs delta、廣播放大、快照自洽。M4 用全量 JSON 就夠；先正確再優化。

  54. 54H8 · 匹配入門：怎麼把人湊進同一房h · l2 · ready

    入隊、湊滿 N 人、超時處理。Arena Mini 用房號當手動匹配；自動匹配先建立正確心智模型。

  55. 55H9 · 規則與 I/O 分離：game 不該 import websocketh · l2 · ready

    純邏輯可單測；hub 只負責收發。時間與隨機數可注入——讓 go test 不需開 port。

  56. 56H10 · Lab：Arena Mini 權威對戰檢查點h · l2 · ready

    把 H1–H9 落到可玩的一局：Ready、Tick、Input、State 廣播。雙人同步過關，才算 H 卷收束。

  57. 57I0 · I 卷導讀：資料放哪裡，比怎麼寫 SQL 更重要i · l1 · ready

    記憶體、Redis、資料庫各管什麼；為什麼 tick 熱路徑絕對不該狂寫庫。

  58. 58I1 · 持久化邊界：什麼時候才該寫進硬碟i · l2 · ready

    熱路徑 vs 冷路徑；事件邊界寫入；帳號資產跟進行中對局為什麼不能同一套語意。

  59. 59I2 · database/sql：連線池、context，還有 Repo 這層皮i · l2 · ready

    標準庫資料庫介面怎麼用；為什麼不要每個請求 Open 一次；Room 熱路徑為什麼不該直接握 DB。

  60. 60I3 · Redis 用途地圖：該上的時候再上i · l2 · ready

    在線、排行榜、pubsub、分散鎖——各適合什麼；單機 demo 為什麼可以先不裝。

  61. 61I4 · 快取一致性：允許錯多久，比追求永遠正確實際i · l2 · ready

    旁路快取、TTL、寫穿；遊戲裡哪些資料可以舊一秒，哪些不行。

  62. 62I5 · 背景任務與結算：離開 tick，排好隊再寫i · l2 · ready

    有界佇列、worker pool、至少一次投遞與冪等；關服時要排空，不能直接閃人。

  63. 63J0 · J 卷導讀：能玩還不夠，要能關、能看、能守j · l1 · ready

    上線前補齊觀測、優雅關閉、壓測、安全與擴展邊界——讓 Arena Mini 從 demo 變成可操作的服務。

  64. 64J1 · 結構化日誌 slog：出事時要找得到人j · l2 · ready

    用 log/slog 打帶欄位的日誌；房間、玩家、請求能關聯，別再靠人肉 parse 字串。

  65. 65J2 · Metrics：現在系統怎樣，一眼看數字j · l2 · ready

    用原子計數做連線數、房間數、訊息速率；先提供 JSON /metrics，之後再換成 Prometheus。

  66. 66J3 · 優雅關閉：Ctrl+C 也不該直接蒸發j · l2 · ready

    收到 SIGINT／SIGTERM 後：停接新連線、停 tick、排乾 in-flight，再離開——給玩家與資料一個體面結局。

  67. 67J4 · 壓測：先有假設，再漸進加壓j · l2 · ready

    用假 client 拉高連線與訊息量；對照 metrics，找出是廣播、鎖還是編碼先爆——別一次開滿只看 crash。

  68. 68J5 · 安全基線：客戶端說的話，預設都不可信j · l2 · ready

    驗證命令、限制大小與速率、守住秘密與信任邊界；權威 Server 是反作弊第一層，但不是全部。

  69. 69J6 · 容量與廣播放大：人一多，流量不是線性的j · l2 · ready

    用粗估公式感受頻寬與 CPU；搞懂全量互相廣播為何接近 O(N²)，以及可以怎麼降流量。

  70. 70J7 · 水平擴展提醒：有狀態房間不能亂 round-robinj · l2 · ready

    搞懂 sticky／房間親和、Gateway 與 Game 切分；為什麼同一房的封包不能隨便打到不同機器。

  71. 71J8 · Lab：關得乾淨，再壓一下j · l2 · ready

    把 metrics、優雅關閉、load-client 串成一套操作：看數字、加壓、Ctrl+C，留下你對瓶頸的第一個判斷。

  72. 72K0 · K 卷導讀：收束——你走到哪了，下一步去哪k · l1 · ready

    不灌新理論：用複習地圖把主路徑串起來，再進自評清單與延伸任務，把理解變成作品。

  73. 73K1 · 自評清單與延伸任務：勾得下去，才算真的會k · l1 · ready

    用可勾項目確認主路徑能力；每項說明在檢查什麼。再從延伸任務挑一塊做成作品集。

  74. 74P0.0 · 為什麼要拿遊戲 Server 當練習目標？p0 · l1 · ready

    這不是遊戲美術課。我們用一個迷你遊戲 Server，把後面學的 Go 技能接到能跑、能驗證的東西上。

  75. 75P0.1 · 為什麼學 Go（而不是把 Python 換皮）？p0 · l2 · ready

    搞懂 Go 刻意做了哪些取捨：編譯、靜態型別、併發、好部署——以及什麼時候它特別適合遊戲 Server。

  76. 76P0.2 · 專案長什麼樣？module、package、目錄p0 · l2 · ready

    從 Python 的腳本／套件心智，換成 Go 的 module（依賴邊界）與 package（編譯與可見性邊界）。

  77. 77P0.3 · 型別怎麼想？靜態檢查與零值p0 · l2 · ready

    從 Python 動態型別切到 Go：編譯期契約、零值（zero value）是設計的一部分、轉換必須寫清楚。

  78. 78P0.4 · 錯誤是回傳值，不是例外跳轉p0 · l2 · ready

    Go 用 error 當值往上傳，控制流留在函式裡。遊戲 Server 的滿房、逾時、非法操作都是日常路徑。

  79. 79P0.5 · 沒有 class 繼承？用 struct、方法、介面組合p0 · l2 · ready

    Go 不靠繼承樹。資料放 struct、行為綁方法、能力用 interface 描述；編譯期檢查你有沒有做到。

  80. 80P0.6 · 併發先建立直覺（詳情在 C 卷）p0 · l2 · ready

    goroutine 不是 OS thread，也不是 asyncio 的直接翻譯。先搞懂：執行、通訊、多路等待，以及亂開會怎樣。

  81. 81P0.7 · 日常工具鏈：build、test、fmt、vet、modp0 · l1 · ready

    把 go build／test／fmt／vet／mod 變成肌肉記憶。格式化不爭論、測試在標準位置、競態偵測器內建。

    GoLearning 是可循序的主路徑，也是可查的手冊。搞懂必讀標記、深度分層，以及檢查點怎麼驗收。
