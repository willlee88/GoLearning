## 1. 專案願景

打造一個**廣覆蓋、可深讀**的 Go 學習網站：

1. **以 Python 為認知橋樑**——不假設零程式經驗，但**不把 Go 教成「有型別的 Python」**；每個關鍵差異都講「為什麼這樣設計」與「執行期／編譯期實際發生什麼」。
2. **以深刻理解為品質線**——覆蓋面廣，但章節分層：**入門能用 → 機制深挖 → 反模式與取捨 → 遊戲 Server 落地**。
3. **以遊戲 Server 為主應用軸**——語言與標準庫的廣度，最終收斂到可運行的多人後端（大廳、房間、匹配、tick、狀態同步、觀測與擴展）。

學習者可以：

- 走完整主路徑（Python → Go 心智轉換 → 併發與工程 → 網路 → 遊戲 Server → 生產化）
- 當手冊查主題（slice 底層、interface 動態、scheduler、逃逸分析、HTTP/2…）
- 對照 Python／asyncio／多執行緒的舊經驗，建立正確的 Go 模型
- 完成多個可執行範例與至少一個端到端 **Arena Mini** 遊戲 Server demo

### 1.1 成功標準（Definition of Done）

1. **廣覆蓋目錄**：語言、工具鏈、標準庫核心、併發、測試、模組、網路、資料、觀測、架構，以及遊戲 Server 專題皆可導覽。
2. **深度可驗證**：關鍵主題具備「機制／記憶體或執行模型／與 Python 對照／常見誤解／練習」結構；非僅 API 清單。
3. **Python→Go 轉換路徑**：首卷有完整「心智模型遷移」專章，之後章節維持可選的「來自 Python」側欄。
4. **範例可跑**：廣覆蓋章節中，標記為 *必練* 者皆有 `examples/` 可編譯程式；進階章可有 *選讀實驗*。
5. **遊戲 Server 主線**：端到端 demo + 多類型同步策略的**概念與對照實作**（至少一種完整 demo，其餘以章節 + 精簡 sample）。
6. **網站可本地啟動**：`docker compose up` 或 `make dev` 即可瀏覽。
7. **文件自洽**：本規劃書 + README + 內容樣板足以接續撰寫。

### 1.2 內容哲學：廣覆蓋 × 深刻理解（如何同時做到）

| 原則 | 做法 |
|------|------|
| **廣而不水** | 每個主題分 **L1 能用 / L2 機制 / L3 深潛**；預設正文寫到 L2，L3 摺疊或獨立「深潛」頁 |
| **深而不窄** | 深度花在 *心智模型、執行語義、取捨*，而非堆砌冷門 API |
| **Python 是跳板不是枷鎖** | 先對照降低摩擦，再**刻意拆掉** Python 直覺（GIL、duck typing 執行期、預設傳參考的誤解等） |
| **應用錨定** | 廣覆蓋的終點是能讀、能改、能設計遊戲 Server；非成為語言律師考試 |
| **雙導覽** | **學習路徑**（建議順序）+ **主題索引**（A–Z / 分類樹）服務「廣覆蓋查閱」 |

## 5. 教學設計：給 Python 背景的「深刻理解」

### 5.1 每章固定骨架（樣板）

1. **本章你會建立的心智模型**（1 段話）  
2. **Python 對照**（行為相近／貌合神離／Go 獨有）  
3. **L1 能用**：最小可跑例子  
4. **L2 機制**：編譯、記憶體、執行語義、標準庫契約  
5. **L3 深潛**（可選）：逃逸分析、彙編級直觀、runtime 行為、規格細節  
6. **請丟掉的 Python 習慣**（明確條列）  
7. **遊戲 Server 連結**（即使是語言章也盡量一句「用在哪」）  
8. **練習**：必做 1 + 選做 1–2  
9. **常見坑與如何用工具看見**（`go test -race`、`go vet`、pprof、`GODEBUG`…）  
10. **延伸閱讀**：官方文件錨點  

### 5.2 Python → Go 必拆的迷思（貫穿全文）

| Python 直覺 | Go 要建立的模型 |
|-------------|-----------------|
| 動態型別、執行期才炸 | 靜態型別、編譯期契約；interface 是**方法集**不是繼承樹 |
| 一切「像參考」 | 值語意為預設；pointer 明確；slice/map/channel 的「描述符」語意 |
| GIL 下的執行緒心智 | **M:N scheduler**、goroutine 便宜但非魔法；記憶體模型與 race |
| `asyncio` 單一事件迴圈 | channel/`select`/多 goroutine；何時用 sync、何時用 CSP |
| 例外控制流 | `error` 值傳遞；何時 `panic`；wrap 與哨兵錯誤 |
| 類別繼承擴充 | **組合優於繼承**；小 interface；接受 interface、回傳具體型別（慣例） |
| 虛擬環境 + pip 直覺 | module、語意化版本、`go.mod`、最小版本選擇 |
| 腳本式「跑完就結束」 | 長生命週期服務：graceful shutdown、context 樹、背壓 |

### 5.3 「深刻」的操作性定義（寫作檢查清單）

一章若要標成 **深度章**，至少滿足 3 項：

- [ ] 說清 **資料放在哪**（stack/heap 直觀、是否共享）  
- [ ] 說清 **誰擁有生命週期**（誰 cancel、誰 close、誰 Wait）  
- [ ] 說清 **併發下是否安全** 與如何驗證  
- [ ] 給出 **錯誤示範 → 修正** 對  
- [ ] 連到 **遊戲 Server 真實壓力**（熱路徑、廣播放大、鎖粒度）
