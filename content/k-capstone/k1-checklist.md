## 這章你會搞懂什麼

自評不是考試分數，是問自己：

> 半夜只有我一個人時，這些東西我能不能解釋、能不能跑、能不能改一小刀？

下面每項都加了「人話說明」——不要只機械打勾。  
勾之前，最好能對鏡子講 30 秒，或真的打開程式操作一次。

延伸任務是選做作品集：挑你有興趣的一塊做完，比全都開通卻半成品更有價值。

## Python 對照

就像你寫完教學專案後的 checklist：  
「我會不會處理錯誤？會不會測併發？會不會部署時優雅重啟？」  
差別只是題目換成 Go + 即時房間。

## 自評清單

### 語言與資料結構

- [ ] **能解釋 slice 共享與 map 非併發安全**  
  檢查什麼：兩個 slice 可能共用底層陣列；map 同時讀寫會炸，需要 Mutex 或單一擁有者（A8／C5）。  
  怎麼驗證：講得出「為什麼這裡要拷貝／要加鎖」，或寫過被 `-race` 抓到再修好的例子。

- [ ] **能用 `errors.Is` 與 wrap**  
  檢查什麼：錯誤要可包一層語意又留住根因；比對用 `errors.Is`／`As`，不是比字串（B 卷）。  
  怎麼驗證：看一段 `fmt.Errorf("...: %w", err)` 能說出呼叫端怎麼判斷。

### 併發

- [ ] **能讀懂 `-race` 報告**  
  檢查什麼：不是會背旗標，而是看到報告知道「誰在讀、誰在寫、哪個變數」（C6）。  
  怎麼驗證：對 `examples/c06-race-lab` 能說明 broken 為何紅、safe 為何綠。

### 遊戲後端核心

- [ ] **能畫 Room 狀態機**  
  檢查什麼：lobby／playing／ended（或你專案的 phase）怎麼轉、哪些命令在哪些相合法（H3）。  
  怎麼驗證：在紙上畫圓圈與箭頭，能對著 Arena Mini 行為講一遍。

- [ ] **能說明權威 Server 與 input 的差別**  
  檢查什麼：客戶端送意圖（input），Server 算真相（位置、碰撞、得分）；為什麼直傳座標危險（H4／J5）。  
  怎麼驗證：用自己的話舉一個作弊場景，再說權威如何擋住。

- [ ] **能跑 Arena Mini：雙人移動、碰撞得分、結束回大廳**  
  檢查什麼：主路徑不是「碼有在」而是「玩得出結果」。  
  怎麼驗證：本機 `go run ./cmd/server`，兩人同房 Ready，打到得分與 ended，再回 lobby。

### 可上線基線

- [ ] **能解釋優雅關閉步驟**  
  檢查什麼：信號 → 停遊戲迴圈 → `Shutdown`（含超時）→ 離開；不是直接蒸發（J3／J8）。  
  怎麼驗證：Ctrl+C 時對得上日誌順序，能說為什麼先 `hub.Close`。

- [ ] **能對 `/metrics` 加壓觀察**  
  檢查什麼：會看 connections／messages 等數字，並搭配 load-client（J2／J4／J8）。  
  怎麼驗證：壓測前後有對照，寫得出一句瓶頸猜測。

## 怎麼寫（自評怎麼做比較實在）

建議流程：

1. 從頭到尾勾一輪，不熟的標成「黃」。  
2. 黃的回去對應卷，只補那一塊。  
3. 再跑一次 Arena Mini + J8 操作。  
4. 剩下來仍黃的，寫進你的學習筆記當下一週目標。  

不要為了「滿勾」而勾——這清單是給你自己用的地圖。

## 延伸任務（選做作品集）

挑 **一個** 做完最好。做之前先寫「完成定義」（例如：README 有截圖、有測試、有前後對照數字）。

1. **碰撞得分 + Ended 打磨**  
   Arena Mini 已有基本規則；你可調參數、加規則說明、補測試邊界（同時撞線、超時勝負）。  
   學到：規則純函式可測（`internal/game`）。

2. **重連 session TTL**  
   斷線後短時間內用同一身份回房，狀態還在；逾時才清。  
   學到：session、信任邊界、房間成員生命週期（H2／J5）。

3. **Prometheus 格式 metrics**  
   在現有計數上增加（或改成）Prometheus 文字輸出，用本機 Prometheus／Grafana 刮一次。  
   學到：J2 的輸出層可替換，指標語意不變。

4. **Protobuf（或其它二進位）替代 JSON state**  
   同一份狀態用較小編碼廣播，用壓測對照 `messages`／CPU。  
   學到：J6 容量與協定成本；別忘版本相容（G3）。

5. **第二種遊戲規則（回合制 sample）**  
   另做一個小 room：回合制下棋／卡牌也行，重用信封與 hub 思路。  
   學到：把「tick 權威」與「回合權威」分開，避免腦中只有一種遊戲。

## 為什麼要做延伸任務

課程教的是地圖；作品集證明你會走路。  
面試或自介時，「我改過同步格式並用壓測對照」比「我看完教程」具體得多。

## 遊戲 Server 會用在哪

你的下一步很可能是：

- 把 Arena Mini 當骨架，換自己的玩法  
- 或抽出 hub／協定層，接到真實客戶端  

不管哪條路，清單上的併發、權威、觀測、關閉，都會一直跟你。

## 請丟掉的舊習慣

1. 清單全勾但講不出來。  
2. 延伸任務並行五條，最後 git 一團亂。  
3. 只改功能、不留 README／測試——一週後自己也忘了。

## 動手練習

### 必做

1. 誠實勾完上面清單；黃的至少補一項並重勾。  
2. 從延伸任務選一個，寫下完成定義（三行以內）。  

### 選做

1. 錄一段 1～2 分鐘操作影片：進房→對戰→metrics→關服。  
2. 為你的改動開一個小 README：動機、怎麼跑、前後對照。

## 常見坑

- **用「我當時有讀過」代替「我現在講得出」**：記憶會褪；講不出就維持黃。  
- **延伸任務做得太虛**：沒有測試、沒有對照數字，很難證明變好。  
- **改爆主路徑又不懂怎麼回滾**：小步提交；先讓 `go test ./...` 綠著。
