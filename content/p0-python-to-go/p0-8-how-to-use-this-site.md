## 這章你會搞懂什麼

GoLearning 同時是兩種東西：

1. **可循序的主路徑** — 像一門課，從 P0 走到 K  
2. **廣覆蓋手冊** — 像文件站，用搜尋／卷冊當 API 手冊查  

深度用 **L1／L2／L3** 分層：避免「百科變水文」，也避免「一上來就被 runtime 細節淹死」。

讀完你要知道：接下來怎麼走、什麼叫必讀、範例要怎麼跑、檢查點大概驗什麼。

## 先跟 Python 對一下

把本站想成：

| 本站元件 | 比較像你熟悉的什麼 |
|----------|---------------------|
| **主路徑** | 一門「從 Python 轉 Go」的課程大綱 |
| **卷冊索引** | 文件站（像查 Python docs） |
| **`examples/`** | 可執行的 notebook／腳本倉庫 |
| **`demo/arena-mini`** | 期末小專題實驗室（不是美術作品） |

差別是：我們會一直把語言細節接到「遊戲 Server 會用在哪」。

## 怎麼寫（建議走法）

這裡的「怎麼寫」比較像「怎麼走」：

1. **先順完 P0**（你就在這裡）— 建立心智，不要急著狂抄語法。  
2. 進入 **A 卷** 打語言地基；遇到併發名詞先記個連結，細節放到 **C 卷**。  
3. **C 卷** 認真做 race lab——這是「有沒有深刻」的分水嶺。  
4. **F → H** 接到網路與遊戲 Server；邊做邊回鏈語言章。  
5. **K Capstone** 收束，用 demo 自評。  

標記怎麼看：

- **必讀**：frontmatter 裡 `path_required: true`  
- **選讀／深潛**：標 L3，或 `path_required: false` 的廣覆蓋章  

章節若有 `example:`，請到 repo 對應路徑本機跑 `go test`／`go run`——只收藏文章等於沒學。

## 為什麼這樣設計／底層在幹嘛

### 為什麼要 L1／L2／L3

| 標記 | 意義 | 你什麼時候讀 |
|------|------|----------------|
| L1 | 能用、最小例子 | 先求跑通、建立肌肉 |
| L2 | 機制與契約（預設深度） | 主路徑多數章的主力 |
| L3 | 深潛、可先略過 | 有餘力或卡住真因時再挖 |
| `status: ready` | 可以安心學 | — |
| `status: stub`／`draft` | 佔位，之後補 | 別硬啃未完成稿 |

若不分層，新手容易在第一週掉進逃逸分析；若只有 L1，又會變成「會打字不會判斷」。分層是為了**同一條路徑服務不同深度**。

### 為什麼每章都硬凹「遊戲 Server」

因為沒有錨點，知識容易散成詞條。有錨點，你才知道「這章到底為了哪塊 Server 能力」。即使是字串章，也可能接到聊天過濾、協定欄位這類落點。

### 進階可先略過

- 貢獻內容時用 `content/_templates/lesson.md`。  
- 用 `scripts` 裡的檢查腳本驗證連結與 frontmatter（會持續補齊）。  

## 遊戲 Server 會用在哪

從現在起，多數章會有「遊戲 Server 會用在哪」——這是本站跟一般 Go 教學的差別。

你的終點之一是 `demo/arena-mini`：雙開瀏覽器、進房、看狀態轉。前面所有工具鏈、型別、錯誤、併發預告，都是在為它鋪路。

## 請丟掉的舊習慣

1. **只收藏文章，不跑例子** — 本站的例子是正文的一部分。  
2. **跳過錯誤處理，直接貼 Server 範例** — 滿房與壞輸入會天天打你臉。  
3. **用「能跑」代替「理解 race 與生命週期」** — 能跑的錯程式很多；C 卷不要略。  

## 動手練習

### 必做

1. 在網站標完 P0 進度（若進度功能已啟用）。  
2. 執行 `examples/p0-config-stats`，用自己的話寫 **5 條** Python vs Go 差異（這是 P0 檢查點）。  

### 選做

1. 瀏覽 `docs/規劃書.md` 的卷冊地圖，標出你最想先深讀的 3 個主題。  

## 常見坑

- **內容標 `stub` 還硬讀**：先看 frontmatter 的 `status`。  
- **範例跑不起來**：確認 Go ≥ 1.22，並且人在正確的 module 目錄。  
- **想一次讀完整個站再動手**：會迷失；順主路徑、跑例子、再回頭查手冊。
