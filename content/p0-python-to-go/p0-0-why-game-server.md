## 本章你會建立的心智模型

GoLearning **不是遊戲開發課**。  
「遊戲 Server」是整條學習路徑的**應用錨點**：把型別、錯誤、併發、網路、協定、權威狀態、觀測與關機，接到一個你能雙開瀏覽器驗證的東西上。

**Arena Mini** 是那個最小可運行的終點實驗室，不是作品集美術展示。

## 為什麼需要「終點」？

廣覆蓋課程容易變成章很多、但學完不知道用在哪。終點 demo 讓你能回答：

> 我學的這些，合在一起能不能撐住一個即時、多人、有狀態的後端？

| 只讀文章 | 有 Arena Mini |
|----------|----------------|
| 「channel 好像懂」 | 連線 loop + 房間 tick 真的在跑 |
| 「記得要處理 error」 | 滿房／非法 phase／壞 input 有路徑 |
| 「race 很重要」 | registry 與廣播有鎖與測試 |
| 「HTTP 會寫」 | 還有長連線 WS 與 state 廣播 |

## 為什麼選「遊戲」而不是 Todo API？

CRUD 也能教 `net/http`，但較難同時逼出：

1. **長連線** — 不是 request 結束就沒事  
2. **共享可變狀態** — 多玩家、race、誰擁有資料  
3. **時間節奏（tick）** — 固定步進，而非每個請求獨立  
4. **權威與信任邊界** — 客戶端送意圖，Server 擁有真相  
5. **廣播放大** — 人數上升時流量與 CPU 怎麼爆  

這些正是 Go 常被用在即時後端／閘道／遊戲 Server 的原因，也貼近「學過 Python、想深刻理解 Go」的目標。

## 刻意做得很小

| 有 | 沒有（刻意） |
|----|----------------|
| 進房、Ready、移動、state | 華麗畫面、關卡編輯 |
| 權威 input、20Hz tick | 完整 MMO、無縫地圖 |
| metrics、優雅關閉 | 付費、帳號大系統 |

目的：

1. 焦點在 **Server 與 Go**，不是 Unity／美術  
2. 短時間能跑通，不拖垮課程  
3. `internal/game` 可單測，規則與 I/O 分離  

之後若加碰撞／得分／Ended，是**玩法完整度**加分，不是本課存在的理由。

## Python 對照

你可能用 Flask／FastAPI 寫過 API；那些多半是**短請求、無共享即時狀態**。  
遊戲 Server 更接近：長生命週期行程 + 多客戶端事件 + 記憶體中的權威世界。學 Go 的價值在這裡特別明顯。

## 請丟掉的誤解

1. 「這課要培養遊戲企劃」— 否。  
2. 「先做出完整遊戲再學 Go」— 否，先最小閉環。  
3. 「聊天室就夠了」— 可以替代，但較難練 tick／權威／廣播。
